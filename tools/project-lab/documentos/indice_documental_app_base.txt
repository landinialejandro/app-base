OBJETIVO DEL DOCUMENTO

Este documento define el índice documental activo del proyecto app-base.

Su función es ordenar qué documentos existen, qué responde cada uno, cuándo deben leerse y qué frontera documental protege cada documento.

Debe servir para:

identificar documentos activos
clasificar documentos por familia
definir la pregunta principal de cada documento
orientar lectura por frente activo
evitar recorrer documentos innecesarios
evitar duplicación documental
evitar contradicciones por uso de documento incorrecto
facilitar continuidad entre sesiones
facilitar intervención de otras personas o sistemas IA
mantener trazabilidad documental del proyecto

No define:

contenido completo de cada documento
doctrina interna de cada frente
reglas técnicas de implementación
seguridad detallada
arquitectura completa
navegación completa
UI completa
roadmap operativo
historial de cambios
audiencia y usos del producto

Regla:

este documento indica dónde leer.

No reemplaza la lectura del documento especializado correspondiente.
<<END SECTION>>

<<SECTION: PRINCIPIO GENERAL DE LECTURA DOCUMENTAL>>
SECTION_VERSION: 00001

PRINCIPIO GENERAL DE LECTURA DOCUMENTAL

La documentación activa debe leerse según necesidad real.

No todos los documentos deben leerse en todos los chats, auditorías o intervenciones.

Orden base para trabajo técnico:

1. contexto_fijo_proyecto_app_base

2. seguridad_acceso_proyecto_app_base

3. plantilla_inicio_chats_proyecto_app_base

4. documento especializado del frente activo

5. código real, runtime, auditoría o evidencia Project Lab cuando corresponda

Regla:

los documentos rectores dan marco.

Los documentos especializados dan materia.

Project Lab y runtime dan evidencia.

No se debe resolver un frente desde memoria, analogía o documento incorrecto.

NO SE ASUME.

NO SE SUPONE.
<<END SECTION>>

CRITERIOS PARA USO POR IA

Una IA que intervenga en app-base debe usar este índice para decidir qué leer antes de responder, auditar, proponer, documentar o generar código.

Reglas:

no leer todos los documentos por reflejo si el frente activo es acotado

no responder desde memoria si existe documento especializado aplicable

no usar un documento de memoria como fuente primaria de doctrina si existe documento rector o especializado

no usar todo_proyecto_app_base como doctrina estable

no usar welcome_usuario_app_base para deducir arquitectura

no usar monetizacion_proyecto_app_base para deducir permisos

no usar contexto_fijo_proyecto_app_base para resolver permisos detallados

no usar seguridad_acceso_proyecto_app_base para resolver UI

no usar base_visual_proyecto_app_base para autorizar acciones

no usar mapa_navegacion_relaciones_app_base para deducir ownership de entidades

no usar mapa_entidades_app_base para deducir navegación real

no usar decisiones_vivas_app_base como reemplazo de evidencia runtime

no usar errores_y_lecciones_app_base como prueba de error vigente sin auditoría

Regla final:

la IA debe leer el documento correcto para la pregunta correcta.

Si falta evidencia, debe pedirla.

DOCUMENTOS CANDIDATOS O FALTANTES

Documento creado en esta línea:

estandar_documental_app_base

Función:

definir cómo documentamos, qué pregunta responde cada documento y cómo iniciar documentación en futuros proyectos.

Estado:

activo.


Documento creado en esta línea:

indice_documental_app_base

Función:

mapear documentos activos, lectura recomendada, fronteras y precedencia.

Estado:

activo.


Documento creado en esta línea:

audiencia_usos_producto_app_base

Función:

definir para quién se construye app-base, qué usos principales sostiene, qué sabe la audiencia, qué le frustra, qué objeciones tiene, para quién no es el producto y qué debe saber una IA para no optimizar en abstracto.

Estado:

activo.


Documentos candidatos futuros:

ninguno definido en este corte.

Regla:

la existencia de candidatos o faltantes no habilita creación automática de documentos nuevos.

Todo documento nuevo debe cumplir el estándar documental.

REGLA DE ACTUALIZACIÓN DEL ÍNDICE

Este índice debe actualizarse cuando:

se crea un documento nuevo
se elimina un documento activo
un documento cambia de función
un documento cambia de familia
un documento cambia su pregunta principal
se detecta una contradicción de precedencia
se incorpora un frente especializado nuevo
se modifica la regla de lectura por frente activo

No debe actualizarse por:

cambios menores de redacción
ajustes internos que no alteren función documental
nuevas secciones que no cambien pregunta principal
auditorías sin impacto documental
pendientes coyunturales

Regla:

el índice debe ser estable, breve y útil.

No debe convertirse en historial de actualizaciones.
<<END SECTION>>

<<SECTION: REGLA FINAL>>
SECTION_VERSION: 00001

REGLA FINAL

Este índice existe para que una persona o una IA pueda responder rápidamente:

qué documento necesito
para qué sirve
qué pregunta responde
qué no debo buscar ahí
qué documento prevalece
qué evidencia falta

Si una intervención no sabe qué documento leer, debe comenzar por este índice.

Si el índice no resuelve qué leer, debe revisarse el estándar documental o pedir precisión del frente activo.
